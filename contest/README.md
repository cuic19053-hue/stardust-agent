先看[实施计划与验收条件](./PLAN.md)。当前 [立项医生原型](./qoder-site/index.html) 支持导入 TXT、DOCX 和可提取文字的 PDF，选择诊断视角，逐段运行本机 Qwen，展示原句、问题和建议，并可编辑片段、生成修改建议、复查和手动替换。草稿与记录对照、预算加总和限定批次的人数规则保留在辅助工具中。案例中的项目记录与数字为虚构；学校规则链接指向历史批次原件。

规则与模型都可能遗漏或误判，不能验证事实真实性，也不代表满足申报资格。用户可返回修改并下载包含当前填写内容的核对记录。尚未完成独立用户盲试、公开部署或赛事资格确认。该原型由 Codex 编写；Qoder 曾选择 Qwen3.8-Flash，但账户提示 Credits 不足，模型未生成代码，不应将该过程描述为 Qwen 开发成果。赛事对 Qoder 开发和部署的要求仍需在后续实际满足。

## 启动本机 Qwen 版

先运行 Ollama，准备 `qwen2.5:7b`，再从仓库根目录执行：

```bash
cd contest/qoder-site
../../.venv/bin/python -m backend.app
```

在本机浏览器打开 <http://127.0.0.1:8765/>，载入模拟申报书或导入材料，点击「根据材料推荐视角」，模型按材料实际覆盖的板块决定视角数量（2 到 5 个，长文按章节标题抽样后推荐，不固定为四个），然后可修改、增删及勾选视角，再开始会诊。也可直接开始，会自动先推荐视角；若模型推荐失败，可以手动添加。最多支持 5 个视角。每个视角独立诊断后，每条意见按序号轮流交给不同视角复核（复核者始终与被诊断视角不同），展示赞同、质疑或待核的理由并尽量关联片段原文，完成语汇总三类数量；单视角时不会进行交叉复核。修改建议会带上该意见的交叉复核结论，要求建议回应质疑或待核点。这些角色是同一本地模型的不同提示和独立调用，并非独立模型或真人评委。另选已安装的本地 Ollama 模型可设置 `CONTEST_OLLAMA_MODEL`；默认 `qwen2.5:7b`。

导入文件时，文件传至本机服务提取文字；点击角色推荐、会诊、改写或复查时，相应正文或片段发给本机服务与本机 Ollama。服务不主动保存这些内容。下载记录由用户主动写入本地文件。模型引文经服务端逐字校验，校验失败时提示该项未完成；引文正确也不等于判断正确或材料真实。长文的角色推荐使用开头、结尾加编号章节标题附近的连续摘录，诊断和交叉复核按片段进行，不能可靠判断跨片段关系。每个片段、每个视角及每条交叉复核均需一次模型调用，耗时随材料长度和视角数量增加。文件最多 2 MB，正文最多 16000 字；扫描件暂不支持 OCR，图表和复杂排版可能无法完整提取，导入后须人工检查。此服务只绑定本机、不带公网访问控制和计费保护，**不能直接公开部署**。

本地运行规则与会诊辅助回归：`node --test contest/qoder-site/tests/`（engine.test.js 覆盖有限词汇判断，consult.test.js 覆盖分段、长文视角抽样和复核者轮转）；模型接口回归：`.venv/bin/python -m pytest -q contest/qoder-site/tests/test_model_api.py`。真实模型的少量虚构案例观察见[模型试运行记录](./MODEL_EVAL.md)，已完成和待完成事项见[验收记录](./ACCEPTANCE.md)；[作品帖草稿](./SUBMISSION_DRAFT.md)中的空项须依据真实情况补充。
