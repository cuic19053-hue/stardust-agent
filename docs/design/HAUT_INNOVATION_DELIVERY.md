# 河南工业大学创新训练项目交付验收

选用河南工业大学 2024 年校级创新训练项目作为历史验收案例。教务处在通知第二部分“申报材料报送”中指定创新项目填写附件 2《创新项目申报表》。这份通知只能用来核对该年度和类型的要求。[教务处原通知](https://jwc.haut.edu.cn/info/1114/7471.htm)

**当前状态**　已验证合成材料的大文件上传、确认、计费恢复和 Word 下载。教务处附件下载需要人工验证码，正式空表及获授权的脱敏材料待取得。原表栏目、版式和生产付费交付均待验收。

## 已自动验证的交付链路

运行 `python -m pytest tests/test_paid_project_delivery.py tests/test_agent_journal.py -q`。测试使用独立项目、SQLite 账本、模拟模型响应和供应商收据。四份约 270 KB 的文本通过上传接口逐份确认。这组材料共生成 468 个索引片段。按相同项目和空对话历史序列化，旧格式为 2,449,572 字节，新格式为 18,590 字节。模型先调用资料检索再写稿。测试在最后一次模型结果写入执行记录后、助手消息提交前模拟中断。

第二个客户端以空白会话打开同一项目，按项目找回中断任务，用运行 ID 接续。核对恢复答复、重复提交、保存后的草稿及下载的 Word。测试比对“准备开展校园观测”和“耗材预算为1200元”，检查账本余额只减少两笔模拟收据的金额。服务重启后的旧格式任务、200 条长消息的恢复边界、材料撤回和未知调用另有回归覆盖。

工作台入口为对话右上角的 **会话选项 → 查看本项目对话任务**。已完成的任务可直接读取答复。接续中断任务时仍校验原消息、模型配置及私有检索授权。遇到调用结果待核对时，先核对上游收据。

## 正式模板自动回归入口

取得正式空表后，核对人在看生成结果之前固定 DOCX 的 SHA-256，标出研究方案应填的位置。案例 JSON 的 `template` 是相对该 JSON 的原表路径，`sha256` 是原表摘要，`research_field` 记录从零开始的 `table`、`row`、`column`，或正文中的 `paragraph`。设置 `HAUT_DELIVERY_CASE` 为该 JSON 的路径，运行 `python -m pytest tests/test_paid_project_delivery.py -k haut_innovation_form -q -rs`。

该用例上传指定原表，走完整付费模拟流程，并核对下载文件中的原表栏位、表数、行数和列宽。缺少正式模板标注时显示跳过。真实写作的事实核对和逐页排版验收另外记录在下表。

## 正式模板与真实交付记录

| 环节 | 验收动作 | 通过条件 |
| --- | --- | --- |
| 固定原件 | 记录学校通知、年份、附件号和原文件 SHA-256。若原件为旧版 Word，另存 DOCX，保留两份文件及哈希，逐页检查转换差异。 | 空表来源与申报年度、项目类型一致，转换后仍保有原栏位和完整签章区。 |
| 标注原始依据 | 独立核对人从授权材料摘录预算、观测进度等原句，记录材料名、确认修订号、页或段；资格和期限另记官方条款与适用对象。 | 每项事实能定位到原文。计划、已完成、尚未确定分别标注，原文缺失或冲突的项目留待核对。 |
| 生成与找回 | 学生上传模板与材料，逐份核对后生成。记录版本、项目和任务 ID，在接收答复期间断开连接，换一台设备登录同一账号，打开原项目查询结果。 | 两端找到同一任务和同一答复。重试同一任务后，账本中的模型调用数与供应商唯一收据数一致。 |
| 保存与下载 | 学生逐项核对并保存。用第二台设备下载 Word，在原表对应单元格或段落查找已保存的事实。 | 每个已知必填项在正确栏位，待确认内容可识别。签字、盖章和评审意见区保留供相应人员填写。草稿仅追加到表格后面时，本项失败。 |
| 逐页复核 | 并排查看空表和下载文件的渲染页，记录表格与合并单元格、页边距、页眉页脚、分页、遮挡或截断。 | 人工标注的必填栏目和版式检查点逐项通过，并保留失败的页码与截图。 |
| 实际成本 | 对照一次完整交付的上游收据、积分预留、最终结算和退款。 | 每笔实扣可对应到原任务，重试没有新增重复调用。存在未决预留时保留待核账状态。 |

记录本份的事实错误数 / 有依据的已核对断言数、漏填必填项 / 应填项、合格版式检查点 / 总检查点，以及该任务的最终实扣。没有分母或没有真实收据的指标记为未测。单个历史表格的结果只适用于该模板版本。

## 发布依赖

云端应用切换前应用 `20261128054323_agent_turn_version_references.sql`。新版调用 `open_v2` 写入材料版本引用，旧版任务继续按原快照恢复。在隔离 PostgreSQL 中可运行 `RUN_POSTGRES_POLICY_TESTS=1 python -m pytest tests/test_material_postgres.py -k agent -q` 核验项目权限、运行找回和租约。生产验收使用已部署的版本和独立测试账号单独记录。
