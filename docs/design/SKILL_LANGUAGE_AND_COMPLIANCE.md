# Skill 语言策略与内容合规规范

> 本文回答两个反复被问到的问题：
> **(a) skills 该用英文还是中文？** **(b) 内容怎么算符合国家规范？**
>
> 结论先行，理由与落地规则在后。所有数字来自 2026-11-15 对仓库全量 35 个
> SKILL.md + 98 个 references 文件的实测。

---

## 一、语言策略：分层，而不是一刀切

### 1.1 结论表

| 层级 | 用什么语言 | 理由（可验证） |
|---|---|---|
| 目录名 | **英文 kebab-case** | Agent Skills 规范要求 `name` 与父目录名一致，而 `name` 只允许 `a-z`、`0-9`、`-`。中文目录名会同时违反两条规则。 |
| `name` | **英文 kebab-case** | 同上。参考实现按 ASCII 判定，中文直接报 `invalid characters`。 |
| `description` | **中文为主 + 英文锚点** | 规范只限长度（≤1024 字符）不限字符集，中文可写。中文对中文 query 是确定性字面召回；末尾加 `（EN: ...）` 补英文召回。 |
| `metadata.triggers` | **中文** | 用户用中文提问，中文触发词是唯一稳定的字面锚点。 |
| SKILL.md 正文 | **中文** | 产物是中文申请材料，中文指令让术语与输出同 token 序列，无跨语言损耗。 |
| references/ | **中文** | 与正文同源；中英混写会造成术语断裂。 |
| 代码注释 | **中文 docstring + 英文标识符** | 注释服务维护者（中文团队），标识符服务 API。 |
| README | **中文主 + 英文镜像** | 已有 `README.md` / `README_EN.md` 双份。 |

### 1.2 为什么正文不能用英文（四条硬理由）

1. **术语零损耗**。「思想汇报」「入党积极分子」「三下乡」「推免」这些词没有
   通用英文对应词。用英文写指令，模型需要先跨语言映射回中文概念再生成，
   映射过程就是失真来源。中文指令与中文输出是同一 token 序列，没有这一步。
2. **文体先验对齐**。中文指令自带书面语语体；英文指令容易带入英文写作习惯
   （topic sentence 前置、被动语态偏好），与中文材料「先叙事后评价」的结构冲突。
3. **规范表只有中文语境下成立**。写作规范块里的禁用词表（「具有重要意义」
   「砥砺意志品质」）和替换动作表（「名列前茅」→「专业 `<排名>/<总人数>`」）
   翻译成英文就变成无意义拼音串，规范直接失效。
4. **门禁脚本依赖中文锚点**。`inject_writing_style.py` 用
   `^##\s.*质检清单.*$` 定位插入点，`verify_skill_integrity.py` 断言
   `"质检清单" in text`。正文改英文会导致这两个门禁全部失配。

### 1.3 token 账要算清楚

实测预加载预算（`name` + `description` + `triggers`）：

| 项 | 字符数 | 说明 |
|---|---|---|
| 35 个 `description` | 6,449 | 含新增英文锚点后 |
| 439 个 `triggers` | ~2,470 | 已去重 |
| 35 个 `name` | 669 | — |
| 合计 | ~9,588 字符 | 平均每 skill 274 字符 |

把 description 全改英文，token 大约省 10%，但会丢掉中文 query 的字面召回。
**用 10% 的预加载预算换召回率，不划算。** 真正该砍的是跨 skill 撞车的触发词
（`三下乡`、`立项申报书`、`大创` 各被 3~4 个 skill 共用），这些不提供区分度，
却全额计入预算——已在本轮移除。

> **修正（2026-11-15 实测）**：这条建议经复核后**不采纳**。
> 418 个触发词里有 12 个跨 skill 共用，但每个 skill 都另有 **5~21 个独有触发词**
> （最少的 `national-project-eval` 也有 5 个），区分度不受影响。
> 反过来，`三下乡`/`立项申报书`/`社会实践` 这类类目词是**用户真实会输入的上位词**：
> 删掉后用户说「帮我写三下乡申报书」将命中不到任何 skill，只剩歧义。
> **结论：共享触发词保留，由根 `SKILL.md` 的路由决策树做二次分流。**
> 该判断已固化为 `tests/test_compliance.py::test_each_skill_has_unique_triggers`。

### 1.4 英文锚点的写法

每条 description 末尾统一追加：

```
……（EN: China International College Students Innovation Competition business plan）
```

- 长度控制在 15~60 字符，整体不超过 300 字符。
- 只写**检索锚点**，不写完整翻译（翻译会让 description 膨胀到 500+ 字符）。
- 已由 `scripts/apply_skill_fixes.py` 的 `EN_ANCHOR` 表统一维护。

**召回实测**：用 12 条英文核心查询测试，加锚点后 **12/12 命中**对应 skill
（`challenge cup` → `challenge-cup`、`western plan` → `western-plan` 等）。
该结果已固化为 `tests/test_compliance.py::test_english_anchor_queries_hit_expected_skill`，
锚点被改动导致召回退化时测试会失败。

> 注意：这是**字面召回**的下界验证。真实触发由语义模型完成，
> 字面命中说明锚点提供了确定性的英文锚点，不保证语义模型一定选中。

## 二、内容合规：七条底线

以下七条已注入全部 35 个 SKILL.md 的写作规范块（`<!-- WRITING-STYLE:START -->`），
并由 `scripts/check_compliance.py` 在 CI 中强制检查。

### 2.1 不代写、不伪造

产出是**草稿底稿**，须由申请人本人核对事实并用自己的语言改写后提交。
禁止生成可直接原样提交的全文，禁止编造成绩、排名、获奖、项目数据、实验结论。

> 上位依据：《高等学校预防与处理学术不端行为办法》（教育部令第 40 号）
> 对「买卖、代写论文」的界定；各校学生手册对申请材料真实性的要求。

### 2.2 政策与金额时效

涉及金额、名额、比例、年限时，一律标注「以你所在学校/当年官方通知为准」。
未拿到通知就留空或写「待核对」，不按往年数字推算。

**已核实的政策口径**（可作为引用基准）：

| 项目 | 标准 | 文号 | 起算 |
|---|---|---|---|
| 本专科生国家奖学金 | 10000 元/人/年 | 财教〔2024〕181 号 | 2024 年起 |
| 本专科生国家励志奖学金 | 6000 元/人/年 | 财教〔2024〕181 号 | 2024 年起 |
| 本专科生国家助学金 | 平均 3700 元，2500—5000 元区间自主确定，可分 2—3 档 | 财教〔2024〕181 号 | 2024 年秋季学期起 |

来源：[财政部 教育部 人力资源社会保障部《关于调整高等教育阶段和高中阶段国家奖助学金政策的通知》（财教〔2024〕181 号）](https://www.gov.cn/zhengce/zhengceku/202410/content_6983670.htm)

### 2.3 文号与统计数据必须可核验

- 只引用能在政府官网、权威媒体核到的文号与数据。
- 写法统一为 `《文件全名》（发文号）`。
- 占位文号（如 `〔20XX〕XX 号`）必须替换为真实文号，不得当作事实交付。

**本轮修正的典型错误**：

| 错误写法 | 正确值 | 来源 |
|---|---|---|
| 《"十四五"国家应急体系规划》（国发〔2021〕109 号） | 国发〔2021〕36 号 | [国务院公报](https://www.gov.cn/gongbao/content/2022/content_5675949.htm) |
| 《中国制造 2025》（国发〔2025〕XX 号） | 国发〔2015〕28 号 | [国务院文件](https://www.gov.cn/zhengce/content/2015-05/19/content_9784.htm) |
| 国办发〔2026〕12 号 / 〔2026〕8 号（未来年份） | 占位 `〔20XX〕XX 号` | 无法核验 |

已核实的常用文号（可直接引用）：

- 《2030 年前碳达峰行动方案》——[国发〔2021〕23 号](https://www.gov.cn/zhengce/content/2021-10/26/content_5644984.htm)
- 《新一代人工智能发展规划》——[国发〔2017〕35 号](https://www.gov.cn/zhengce/content/2017-07/20/content_5211996.htm)
- 《"十四五"国家应急体系规划》——[国发〔2021〕36 号](https://www.gov.cn/gongbao/content/2022/content_5675949.htm)

### 2.4 领导人讲话表述规范

- 用规范全称：「习近平总书记重要讲话」，**不使用「最高领导人」「国家领导人」这类模糊代称**。
- 引用以新华社、人民日报通稿原文为准，不缩写、不改写、不拼接。
- 党的会议、机构名称用全称或规范简称（「党的二十大」「党的二十届三中全会」）。

本轮已清除全仓 15 处「最高领导人」代称，覆盖 6 个 skill 与 5 个 references 文件。

### 2.5 个人信息最小化

- 身份证号、学号、手机号、银行卡号、家庭住址、低保/建档立卡编号等高敏信息，
  非必填不采集。
- 示例与草稿中一律用 `[姓名]`、`[学号]`、`[手机号]` 占位，不写真实值，不落盘留存。
- 全仓已核查：无真实格式的手机号、身份证号、银行卡号（0 命中）。

> 上位依据：《中华人民共和国个人信息保护法》最小必要原则与告知同意规则。

### 2.6 适用范围：申请材料不是党政机关公文

学生申报书、申请书属**个人申请材料**，不套用《党政机关公文格式》（GB/T 9704）
的红头版式。格式以学校下发模板为准。

本轮修正 4 处以《党政机关公文处理工作条例》作为申请书格式依据的误用。

### 2.7 引用与著录规范

- 参考文献著录用 **GB/T 7714**（已有 15+ 个 skill 引用，覆盖充分）。
- 标点符号遵循 **GB/T 15834**，数字用法遵循 **GB/T 15835**，
  语言文字遵循《中华人民共和国国家通用语言文字法》。
- 中文正文用中文全角引号（「」或 ""），不混用英文直引号。

## 三、门禁与回归

| 脚本 | 检查内容 | CI |
|---|---|---|
| `check_compliance.py` | C1 领导人表述 / C2 未来文号 / C3 占位文号 / C4 无来源统计 / C5 绝对化承诺 / C6 诚信底线 / C7 金额时效 / C8 公文误用 | ✅ `--strict` |
| `verify_skill_integrity.py` | I1 受保护块 / I2 索引指针 / I3 frontmatter / I4 重复标题 / I5 质检清单 / I6 空章节 | ✅ |
| `check_skill_description.py` | D1 长度 / D2 何时使用 / D3 触发词 / D4 唯一性 / D5 无栏目清单 / D6 name 格式 | ✅ |
| `check_doc_consistency.py` | 赛道数 / README KB / 索引数量 / Agent Skills 规范 | ✅ `--require-skills-ref` |
| `inject_writing_style.py --check` | 35 个 skill 的写作规范块是否最新 | ✅ |
| `apply_skill_fixes.py` | 本轮审查修复的幂等重放 | 手动 |

### 为什么 `--require-skills-ref` 很重要

原实现里 `skills-ref` 缺失只记 warning，CI 照样绿——**官方规范校验形同虚设**。
现在 CI 显式要求安装，缺依赖即失败。

## 四、贡献者检查清单

提交涉及 skills 内容的 PR 前，本地跑一遍：

```bash
python3 scripts/check_compliance.py --strict
python3 scripts/verify_skill_integrity.py
python3 scripts/check_skill_description.py
python3 scripts/check_doc_consistency.py --require-skills-ref
python3 scripts/inject_writing_style.py --check
python3 -m pytest tests -q
```

若修改了 README 赛道表或 SKILL.md 体量，记得同步 KB 数字：

```bash
python3 scripts/sync_readme_kb.py   # 或按 check_doc_consistency 的报错逐条改
```
