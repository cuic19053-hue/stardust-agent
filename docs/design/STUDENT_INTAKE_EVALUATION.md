# 学生口述转结构化档案：字段与评测方案

本文记录最初 24 例开发基线的设计。后续本机微调结果、五段实测回放和工作台入口见[公开演示与评测](https://agent.stardust.website/student-intake)。

## 项目现状与接入边界

- `server/proposal/personal_materials.py` 已支持从用户确认的单人材料中提取少量标签字段，不能直接处理自由口述。
- `server/proposal/materials.py` 已区分 `confirmed_facts` 与 `planned_items`，并保留来源及变更依赖。
- `server/proposal/tools.py` 的 `save_confirmed_fact` 已要求学生明确确认及原文依据。
- `server/proposal/openai_adapter.py` 已支持非流式 JSON Schema 请求；线上模型目录目前为空，因此本轮选用本机已安装的 `qwen2.5:7b`。

新增的 `student_intake.py` 是无存储副作用的候选结构定义；`student_intake_baseline.py` 直接调用本机 Ollama，测量提取能力，不代表现有聊天产品的端到端表现。

建议未来流程：口述转写 → 提取候选 → 格式与来源检查 → 向学生展示核对/追问 → 明确确认 → 通过已有事实保存边界写入。候选结果不能直接覆盖现有档案；更正应保留版本及确认来源。

## 字段设计

字段字典以 `server/proposal/student_intake.py` 的 `FIELDS` 为准，共41个字段。

| 分组 | 字段 | 注意事项 |
| --- | --- | --- |
| 基本信息 | 姓名、学校、学院、专业、年级 | 不扩写学校/专业简称，不收集身份证、学号、电话、银行卡和详细住址 |
| 申请目标 | 申请类型、类别/赛道、年度、截止日期 | “大创”不能自动判为创新训练；申请意愿与最终类别分开 |
| 学业 | GPA、满分、排名、排名人数、前百分比、范围、期间、挂科门数、英语 | 满分不默认；3/80不自动算百分比；专业排名不等于班级排名 |
| 获奖 | 名称、级别、等次、时间 | 每个奖项独立关联，不能串奖；去年不擅自换算年份 |
| 科研 | 经历、成果 | 无经历与未提供不同；投稿、计划发表与已经发表不同 |
| 学生工作/服务 | 职务、任期、志愿时长 | 时长统一小时，任期保留原文 |
| 项目 | 名称、问题、对象、方法、进展、人数、分工、导师、预算、周期、预期成果 | 方法不能自动补全；拟做原型不等于已有原型；找了两位同学不自动算三人 |
| 家庭经济 | 年收入、家庭人数、困难认定 | 仅明确助学金/国家励志奖学金场景启用；国家奖学金不提取、不追问；允许拒答 |

每个字段不是裸值，而是一条带来源的候选记录：

```json
{
  "field": "academic.gpa",
  "record_id": "self",
  "value": "3.8",
  "status": "approximate",
  "evidence": [{"turn_id": "u1", "quote": "我的绩点大概3.8"}]
}
```

- `stated`：明确自述，不表示外部核验或学生确认。
- `approximate`：大概、约等不精确陈述。
- `planned`：准备、希望、预计等未完成事项。
- `negated`：明确没有；`unknown`：明确不知道；`withheld`：不愿提供；三者值均为 `null`。
- `conflict`：同一期间的说法冲突且未明确更正，值为 `null`，引用双方原话。
- 完全未提及的字段不输出，不能用“无”填空。明确更正取新值，引用更正原文。

`record_id` 关联同一奖项或同一期排名：单值用 `self`，奖项为 `award_1` 等，排名为 `rank_1` 等。第一版对跨学期GPA、复杂课程清单、集体申请、多学生身份切换的建模仍不充分，扩展前应另做评测。数值统一为十进制字符串，单位定义在字段字典；预算和收入用人民币元，避免浮点误差。

追问输出字段ID，程序生成问题预览，每轮最多3项。当前只是评测接口，尚未实现申请类型的完整必填清单和智能问题排序。

## 首轮评测集

`server/evals/fixtures/student_intake/v1/cases.json` 包含24个合成对话，涵盖身份、GPA满分缺失、模糊百分位、分数排名、更正、未解决冲突、不同统计期间、他人/政策/范文、两个奖项、相对时间、否定、计划、金额换算、团队人数歧义、拒答、国奖与励志经济边界、编造请求、ASR歧义和助手无依据陈述。

全部数据为本轮由Agent编写的开发烟测样本，标注状态为 `agent_authored_not_human_reviewed`。不是人工金标，不是独立测试集，不使用真实学生数据，也不用于训练。

两种实验使用相同提示词、模型版本、温度、种子、上下文和输出上限：

1. `prompt`：仅靠提示词要求输出JSON。
2. `schema`：额外传入 JSON Schema 限制解码结构。

每例每种方式先运行1次，建立可复现的初始结果；不修复JSON、不自动重试，也不挑选成功结果替代失败。此比较衡量“是否增加结构约束”，不代表模型之间的优劣。固定种子也不保证跨硬件逐字一致。

## 指标与判分

| 指标 | 定义及局限 |
| --- | --- |
| JSON / Schema 合规率 | 全部尝试为分母；格式、状态值、重复键记录和额外字段均检查 |
| 可用字段 Precision / Recall / F1 | 严格匹配字段、关联ID、值和状态；格式不合格整例不可用，所有金标字段计漏提 |
| 原文引用合规率 | turn_id必须指向user，quote必须逐字出现在对应回合；不等于语义成立 |
| 证据支持召回 | 正确字段还需包含金标的主体/否定/模糊/更正锚点；冲突需双方锚点 |
| 必要追问召回 | 金标要求追问的字段是否出现；不以固定问句逐字匹配 |
| 整例严格通过 | 字段无错漏、引用与锚点合格、必要追问命中、无重复和拒答后追问 |
| 禁止字段/拒答追问 | 在结构有效输出中计数，另人工复核格式失败原文；不能把零计数解读为完全无风险 |
| 延迟与用量 | 端到端P50/P95、供应商报告输出Token、超时数；样本小且含冷启动，仅代表本机 |

数值正确但关联ID错误会计错；这是可用结构的严格要求，不应在报告中直接称为“编造”。别名与非逐字语义等价需经复核后版本化维护，不能看完模型输出随意放宽当轮金标。Precision只反映通过结构校验后的预测；必须与合规率、Recall、F1一并阅读，避免格式失败反而抬高表面精确率。

当前锚点规则只能做机械检查；长引用包含其他主体、选择性断章取义、隐含关系等仍需人工复核。本轮不使用同一个模型为自己评分。

## 扩大评测的方案

在此烟测之后建立至少100个经学生或标注者授权、脱敏的样本：60个开发、20个验证、20个封存测试。按学生/会话及改写家族分组隔离，同一事实的口语改写、对抗版本不得跨集合。这个规模只用于下一阶段试点，不足以证明整体可靠。

建议覆盖：20个单轮、20个多轮补充/更正/冲突、15个奖项和项目多实体、15个否定/计划/单位/相对时间、15个他人/政策/范文/注入、10个经济信息授权与拒答、5个转写歧义。类别应分配到不同集合并报告分组结果。

由两名标注者独立确认值、状态、实体关联、原话和必要追问；分歧仲裁后再封存。语音输入需额外保存经授权的音频与人工转写，单独测ASR和端到端错误；当前文本模拟不构成ASR质量结论。

试点目标（待人工金标校准，不是当前达成值）：Schema≥99%、字段Precision≥98%、Recall≥95%、必要追问Recall≥95%；关键场景中“计划升格成果、冲突静默选值、他人信息归本人、国奖追问经济、拒答后追问”出现即阻止自动入档。任何阶段仍要求用户确认，不能把小样本零失败当成风险为零。

## 复现

```bash
.venv/bin/python server/evals/student_intake_baseline.py \
  --output outputs/evals/student-intake-next --mode both

.venv/bin/python server/evals/student_intake_baseline.py \
  --case unresolved_conflict \
  --output outputs/evals/student-intake-conflict-next --mode both

.venv/bin/python -m pytest tests/test_student_intake_baseline.py -q
```

输出目录必须为新目录。保留manifest、模型digest、源文件与数据SHA256、提示词、Schema、输入快照、完整请求/响应、逐例分数与汇总。源码快照保存在 `execution-source/`，即使之后修改脚本也可核对本轮实际版本。异常尝试保留并计失败。本机Ollama没有按次API账单，硬件/电力成本未计；脚本不会读取生产凭据或改动应用数据库。

用户最新安排：先完成评估；回来后将材料交给Astra讨论后续微调。本轮不启动训练，不创建训练作业，也不把这套开发题当作后续微调的独立验收集。
