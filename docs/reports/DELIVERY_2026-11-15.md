## 三、任务 2(a)：英文还是中文

### 结论：分层，不是一刀切

| 层级 | 用什么 | 为什么 |
|---|---|---|
| 目录名 / `name` | **英文 kebab-case** | Agent Skills 规范硬约束：只允许 `a-z0-9-`，中文直接校验失败 |
| `description` | **中文 + 英文锚点** | 规范只限长度不限字符集；中文对中文 query 是确定性召回 |
| `triggers` | **中文** | 用户用中文提问，中文触发词是唯一稳定字面锚点 |
| SKILL.md 正文 | **中文** | 产物是中文材料，中文指令与输出同 token 序列，零跨语言损耗 |
| 代码注释 | **中文 docstring + 英文标识符** | 注释服务中文维护者，标识符服务 API |

### 四条不能改英文的硬理由

1. **术语零损耗**：「思想汇报」「入党积极分子」「三下乡」「推免」没有通用英文对应词，
   英文指令要先跨语言映射再生成，映射就是失真源。
2. **文体先验对齐**：英文指令易带入 topic sentence 前置、被动语态偏好，与中文材料
   「先叙事后评价」的结构冲突。
3. **规范表只在中文语境成立**：禁用词表（「具有重要意义」「砥砺意志品质」）翻成英文
   就是无意义拼音串。
4. **门禁脚本依赖中文锚点**：`inject_writing_style.py` 用 `^##\s.*质检清单.*$` 定位，
   正文改英文会导致门禁全部失配。

### 落地：35 条 description 加英文锚点

```
……（EN: China International College Students Innovation Competition business plan）
```

**实测召回 12/12**（`challenge cup` → `challenge-cup`、`western plan` → `western-plan` 等），
已固化为测试 `test_english_anchor_queries_hit_expected_skill`。

### token 账

| 项 | 字符数 |
|---|---|
| 35 条 description（含锚点） | 6,331 |
| 418 个 triggers | ~2,470 |
| 合计 | 平均 274 字符/skill，预算 6,500 未超 |

把 description 全改英文只省约 10% token，但会丢掉中文召回——**不划算**。

1. **不代写、不伪造**：产出是草稿底稿，须本人核对并改写后提交

6. **政治表述规范**：会议文件用全称，不用模糊代称

### 5.2 消除「假绿」

原实现里 `skills-ref` 缺失只记 warning，CI 照样绿——**官方规范校验形同虚设**。
现在 CI 用 `--require-skills-ref`，缺依赖即失败。本机安装后实测 **35/35 通过官方规范校验**。

### 5.3 结构优化

- **11 个 skill 的核心章节命名统一**：「§3 6 段结构」→「工作流程总览：6 段结构」
- **根级 references 从闲置变可用**：5 个共享知识文件（2,000+ 行）原先只被 1 个 skill 引用，
  现在 35 个 skill 的索引全部接入，每条带「何时阅读」触发条件
- **写作规范块瘦身**：内联禁用词表（1.9KB×35）外移为指针，单块 7,271→5,933 字节（−18%）

### 5.4 数据修正

- **description 计长偏差**：正则取原始文本会把 YAML 折行算进长度（虚高 79 字符），改用 `yaml.safe_load`
- **version.json 长期失真**：`total_lines` 停在 35,227 长达 3 个月，实际已 35,276；分类行数同样过期，全部重算并加漂移检测
- **重复 triggers**：2 个 skill 内重复项已清理
- **13 条 description 冗余尾句**：删「直接输出可提交的 Word 文档」，回收 215 字符

### 5.5 被推翻的审计建议（诚实披露）

审计建议「删除跨 skill 撞车的 triggers（三下乡/立项申报书/大创）」。
**实测后不采纳**：418 个触发词里 12 个共用，但每个 skill 另有 **5~21 个独有词**，
区分度不受影响；删掉上位词反而让「帮我写三下乡申报书」命中不到任何 skill。
改为新增「独有触发词 ≥3」门禁，兼顾两者。
